# Internationalizing the Session

Research for putting every Visitor-facing string behind a translation: which
library, which translation service, and what this codebase has to change.
Nothing here is decided; the decisions are listed under
[Open decisions](#open-decisions) and each one that lands should become an ADR.

Versions, download counts and prices were checked on **2026-11-11**. External
claims link to the source that owns them; codebase claims carry `path:line`.
Anything marked _inferred_ is reasoning from those sources rather than
something a source states, and everything that could not be confirmed is
collected under [Unverified](#unverified).

## Summary

- **Library: `@nuxtjs/i18n` 10.6.0** (vue-i18n 11 underneath). The repo is
  already shaped for it: `app/utils/date-format.ts:1-5` holds the date formats
  as vue-i18n `datetimeFormats`, and ADR-0009 names the call they become
  (`docs/adr/0009-dates-are-formatted-for-the-visitor-after-load.md:39-45`). It
  is the integration vue-i18n itself recommends for Nuxt, it writes `lang`,
  `hreflang`, canonical and `og:locale` per locale, and its lint plugin was run
  against this repo's ESLint 10 config and works (95 raw-text findings, see
  [Enforcing it](#enforcing-nothing-hardcoded)).
- **URL strategy: `prefix_except_default`**, English at `/` and each other
  locale at `/<code>`, every one prerendered. A prerendered file can only hold
  one language (ADR-0008), so one URL per locale is the only way a translated
  page reaches a Visitor without JavaScript, and the only shape `hreflang` can
  describe. Browser-language redirects stay off; the language is a setting in
  the Command palette, which ADR-0012 already expected
  (`docs/adr/0012-commands-open-in-a-palette.md:14-16`).
- **Translation service: none to start.** The Interface copy is about a hundred
  short strings and the Content about 2,600 words
  (`docs/adr/0010-content-lives-in-typed-modules.md:7-9`), written by one
  author. Locale files in the repo, a machine or LLM first draft, and a human
  read are enough. If an editor UI is wanted later, Tolgee's free cloud plan
  (30,000 words, 3 seats) or SimpleLocalize's Community plan (500 keys) fit;
  the open-source programmes of Crowdin, Transifex and Weblate do not, because
  the repo has no licence file and is not a community project.
- **The hard part is not the library.** It is the Content: 2,600 words of
  prose in typed modules, Recommendations that are verbatim quotes, and Role
  periods built from English month names. ADR-0010 already says translation is
  the trigger to reopen where Content lives
  (`docs/adr/0010-content-lives-in-typed-modules.md:37-39`).

### `@nuxtjs/i18n`

- **Status.** 10.6.0 is the `latest` dist-tag, with nine releases between
  2025-11 and 2026-07 ([npm](https://www.npmjs.com/package/@nuxtjs/i18n?activeTab=versions)).
  The repo was pushed to on 2026-11-11 and is not archived
  ([nuxt-modules/i18n](https://github.com/nuxt-modules/i18n)). It "configures
  **Vue I18n v11**"
  ([installation](https://i18n.nuxtjs.org/docs/getting-started)).
- **Compatibility.** The module declares `nuxt: '>=3.0.0-rc.11'`
  ([`src/module.ts`](https://github.com/nuxt-modules/i18n/blob/main/src/module.ts))
  and is itself developed against `nuxt ^4.6.2` and `vitest ^4.1.10`
  ([`package.json`](https://github.com/nuxt-modules/i18n/blob/main/package.json)),
  which is this repo's line. It needs Node `>=20.11.1`; vue-i18n 11.4 needs
  Node `>= 22` (both `npm view … engines`). `.nvmrc` should be checked against
  that.
- **Routing.** Four strategies, `prefix_except_default` the default
  ([options: `strategy`](https://i18n.nuxtjs.org/docs/api/options)).
  `no_prefix` "relies on browser and cookie detection" and loses custom paths
  and ignored routes unless `differentDomains` is on
  ([routing guide](https://i18n.nuxtjs.org/docs/guide)). Per-locale domains are
  `differentDomains` and `multiDomainLocales`
  ([options](https://i18n.nuxtjs.org/docs/api/options)).
- **Prerendering.** Lazy-loaded messages are served from a Nitro route. For a
  regular `nuxt build`, `experimental.prerenderMessages` writes them into
  `.output/public/_i18n/<hash>/<locale>/messages.json` as static assets;
  "Statically generated sites (`nuxi generate`) already prerender the message
  files", and `prerenderMessages` "is only needed to prerender them for a
  regular `nuxt build`"
  ([options: prerendering messages](https://i18n.nuxtjs.org/docs/api/options#prerendering-messages-as-static-files)).
  This repo is the `nuxt build` case and must not use `nuxt generate`
  (`docs/adr/0008-the-page-is-prerendered-only-the-api-is-a-function.md:52-55`).
  Only messages from locale files are written to those static files; messages
  declared in the vue-i18n config are merged at runtime (same section).
- **Lazy loading.** Enabled by giving each locale a `file` or `files`; files
  are cached by name. A locale file that contains message functions "ships the
  locale in the client bundle"
  ([lazy-load guide](https://i18n.nuxtjs.org/docs/guide/lazy-load-translations)).
  Locale files default to `i18n/locales/`, the vue-i18n config to
  `i18n/i18n.config.ts` (`restructureDir: 'i18n'`, `langDir: 'locales'`)
  ([options](https://i18n.nuxtjs.org/docs/api/options)).
- **SEO.** `useLocaleHead()` produces `<html lang>`, `hreflang` alternates for
  every locale, `og:locale` and a canonical link; it needs `locales` as objects
  with a `language` tag and a `baseUrl`
  ([SEO guide](https://i18n.nuxtjs.org/docs/guide/seo)). The guide describes a
  per-language catchall link rather than naming `x-default`. An experimental
  `strictSeo` mode sets the tags without the composable and "will become the
  default in v11" if it proves stable
  ([new features](https://i18n.nuxtjs.org/docs/guide/new-features)).
- **Browser detection.** `detectBrowserLanguage` reads `navigator` on the
  client or `accept-language` on the server, remembers the result in the
  `i18n_redirected` cookie, and by default only acts on `/`
  ([detection guide](https://i18n.nuxtjs.org/docs/guide/browser-language-detection)).
  In v10 detection and redirection moved to Nitro, and the docs say the old
  implementation "did not work correctly when combined with prerendering which
  this new implementation does"
  ([new features](https://i18n.nuxtjs.org/docs/guide/new-features)). _Inferred:_
  on Vercel a prerendered `/` is a CDN file and no Nitro code runs for it, so a
  server redirect cannot happen there; see [Unverified](#unverified).
- **Typed keys.** `experimental.typedOptionsAndMessages: 'default' | 'all'`
  generates message types from the default locale or all of them; it is off by
  default ([options](https://i18n.nuxtjs.org/docs/api/options)).
- **Bundle.** Defaults are `compositionOnly: true`, `runtimeOnly: false`,
  `fullInstall: true`, `dropMessageCompiler: false`
  ([options: `bundle`](https://i18n.nuxtjs.org/docs/api/options)). The only
  size figures found are a competitor's: nuxt-i18n-micro's own benchmark puts
  `@nuxtjs/i18n` 10.6 at +0.68 MB of code and +3.16 s of build over a Nuxt app
  with no i18n
  ([nuxt-i18n-micro README](https://github.com/s00d/nuxt-i18n-micro#readme)).
  That is one party's fixture; measure this repo instead.
- **Testing.** The module's docs have no testing page
  ([docs tree](https://github.com/nuxt-modules/i18n/tree/main/docs/content/docs)).
  Nuxt's own guide says the `nuxt` environment runs tests "inside a Nuxt app …
  with access to auto-imports, plugins and injections", and that
  `mockNuxtImport` can replace an auto-import once per file
  ([Nuxt testing](https://nuxt.com/docs/4.x/getting-started/testing)).
  _Inferred:_ `useI18n()` and `$t` are therefore the real ones in `test/nuxt`
  with no extra setup, which is what this repo's tests want.

### vue-i18n directly

- vue-i18n's own Nuxt page opens with "We recommend using Nuxt I18n
  (@nuxtjs/i18n)" and calls the hand-rolled plugin a tutorial that "doesn't
  support advanced i18n features (such routing and SEO tags)"
  ([Nuxt integration](https://vue-i18n.intlify.dev/guide/integrations/nuxt)).
- It would be one plugin calling `createI18n` and nothing else: no routes, no
  head tags, no detection. For a single prerendered page that is nearly enough
  until a second locale needs its own URL, and then the routing and `hreflang`
  have to be written by hand.
- v11 is current; v9 and v10 are in maintenance since July 2025
  ([maintenance](https://vue-i18n.intlify.dev/guide/maintenance)). v12 is in
  alpha (`next: 12.0.0-alpha.9`, `npm view vue-i18n dist-tags`) and requires
  Vue 3.6
  ([v12 breaking changes](https://vue-i18n.intlify.dev/guide/migration/breaking12)),
  which this repo is not on.
- Type-safe messages come from passing the default locale's type as a schema
  to `createI18n` or `useI18n`
  ([TypeScript support](https://vue-i18n.intlify.dev/guide/advanced/typescript)).

### `nuxt-i18n-micro`

- A separate implementation, not a vue-i18n wrapper: its dependencies are
  `@i18n-micro/*` packages (`npm view nuxt-i18n-micro dependencies`). It
  "needs Nuxt 3.18 or newer (Nuxt 4 works too)"
  ([getting started](https://github.com/s00d/nuxt-i18n-micro/blob/main/docs/content/guide/getting-started.md)).
- 4.0.0 shipped on 2026-11-03, a week before this was written, with three
  more releases since (`npm view nuxt-i18n-micro time`). 254 stars, one
  maintainer account
  ([s00d/nuxt-i18n-micro](https://github.com/s00d/nuxt-i18n-micro)).
- "Only JSON files are supported", split into a global file and per-page
  files; the same four routing strategies
  ([README](https://github.com/s00d/nuxt-i18n-micro#readme)).
- SEO is on by default (`meta: true`): `lang`, canonical, `hreflang`,
  `x-default`, `og:locale`
  ([SEO guide](https://github.com/s00d/nuxt-i18n-micro/blob/main/docs/content/guide/seo.md)).
- Detection is server-side: a 302 "made on the server before the page
  renders"
  ([locale detection](https://github.com/s00d/nuxt-i18n-micro/blob/main/docs/content/guide/locale-detection.md)).
- It ships its own test helper, `@i18n-micro/test-utils`, wired with
  `mockNuxtImport('useI18n', …)`
  ([testing guide](https://github.com/s00d/nuxt-i18n-micro/blob/main/docs/content/guide/testing.md)),
  and a separate types generator
  ([types generator](https://github.com/s00d/nuxt-i18n-micro/blob/main/docs/content/integrations/types-generator.md)).
- Against it here: no npm provenance on 4.1.1 while every other candidate has
  it (`npm view … dist.attestations`), a one-week-old major, no raw-text lint
  rule found, and ADR-0009's plan is written in vue-i18n's terms.

### Paraglide JS (inlang)

- A compiler: messages become typed, tree-shakable ESM functions
  ([README](https://github.com/generaltranslation/paraglide-js#readme)). The
  package's repository is now `generaltranslation/paraglide-js`
  (`npm view @inlang/paraglide-js repository.url`).
- 3.0.0 was published on 2026-11-03 and 3.2.2 on 2026-11-10
  (`npm view @inlang/paraglide-js time`); the README still says it "is on v2".
- **No Nuxt integration.** The README lists React, TanStack Start, SvelteKit,
  React Router, Astro, Vue, Solid and vanilla Vite; nothing in the repo tree or
  README mentions Nuxt, and the Vue package is one component for messages with
  markup
  ([`framework/vue`](https://github.com/generaltranslation/paraglide-js/tree/main/framework/vue)).
- Static generation needs the locale set by hand before each page renders, and
  "typically requires all locales to have URL prefixes"
  ([SSG docs](https://github.com/generaltranslation/paraglide-js/blob/main/docs/static-site-generation.md)).
- Best type safety and smallest runtime of the set, but routing, head tags and
  the Nitro prerender wiring would all be written here by hand, in a week-old
  major.

### Nuxt Content's i18n

Not applicable. The site does not use Nuxt Content, and ADR-0010 rejected it
(`docs/adr/0010-content-lives-in-typed-modules.md:22-23`). For the record, it
is not an alternative anyway: "Nuxt Content integrates with `@nuxtjs/i18n`",

### `nuxt-intlayer`

Content is declared in `*.content.ts` files next to components, routes are
generated in four modes, and `npx intlayer fill` translates missing entries
with an LLM key of your own
([Intlayer with Nuxt](https://github.com/aymericzip/intlayer/blob/main/docs/docs/en/intlayer_with_nuxt.md)).
About 5,000 downloads a week. It is a whole content system with an optional
CMS, which is more than a hundred strings need, and it would replace
`app/data/` rather than sit beside it.

### Recommendation for this repo

**`@nuxtjs/i18n` 10.6.0, `prefix_except_default`, detection off, messages
prerendered.**

1. **The repo already committed to vue-i18n's shapes.** The date formats are
   `datetimeFormats` entries and ADR-0009 says "the formats copy under each
   locale unchanged and the calls become `d(value, { key: name, timeZone })`"
   (`docs/adr/0009-dates-are-formatted-for-the-visitor-after-load.md:39-45`).
   Any non-vue-i18n option throws that preparation away.
2. **The page is prerendered and SEO is part of the pitch.** Per-locale routes
   prerender as separate files with their own `lang` and `hreflang`; only this
   module and nuxt-i18n-micro do that without hand-written routing.
3. **"Nothing hardcoded" has to be mechanical.** The raw-text rule exists for
   vue-i18n and was run here against ESLint 10.14 and the antfu preset.
4. **Risk is lowest.** A million downloads a week, provenance on npm, an
   organisation behind it, and vue-i18n's own docs point to it.

What it costs: the heaviest runtime of the candidates, a messages endpoint
that has to be prerendered to keep ADR-0008 true, and typed keys that are
still experimental.

### Recommendation

**Translate in the repo, without a platform.**

- The volume is a hundred strings and a dozen records. A platform's job is
  coordinating translators and tracking changes across thousands of strings;
  here `git diff` on a locale file is that tracking.
- The copy is voice, not labels: "I get frontend projects unstuck"
  (`app/data/profile.ts:52-53`), "Tell me who you are."
  (`app/components/session/output/Contact.vue:77`). A machine draft is a
  starting point; each language needs a fluent human pass. The Profile says
  Pavel was born in Cuba and has lived in Minsk since 2011
  (`app/data/profile.ts:78`), so Spanish and Russian are the two languages a
  human pass is available for at no cost.
- Missing and stale keys are caught by lint
  (`no-missing-keys-in-other-locales`), not by a dashboard.

If an editor is wanted anyway: **Tolgee** free cloud is the best fit (30,000
words covers the site in several languages, CLI for CI, MT included), then
**SimpleLocalize** Community if 500 keys and no auto-translation are enough.
The open-source programmes are out: the repo is public but has no `LICENSE`
file, and it is a personal site, not a community project.

### Awkward cases

1. **Command names are identifiers and display text at once.** `cmd` is what
   the Visitor types, what `exec` matches (`app/composables/useSession.ts:296`),
   the `v-for` key (`app/components/session/output/Help.vue:12`) and what e2e
   finds a block by (`docs/agents/testing.md:176-177`). `whoami`, `ls`, `cat`
   and `mail` are shell words, the same in every language. Recommended: `cmd`
   is never translated, `label` always is. The aliases
   (`useSession.ts:122-140`) are English words (`work`, `contact`, `email`); a
   locale may add its own (`experiencia`, `контакты`), but that is new
   behaviour with its own tests, not translation.
2. **Labels live in a module constant.** `commands` is a top-level array
   (`useSession.ts:51-94`) imported as a value by `Terminal.vue:19`, so it
   cannot call `t()`. Either `label` becomes a message key resolved where it
   is printed, or the labels leave the array for a keyed map
   (`commands.whoami.label`) looked up by `output`.
3. **Sentences assembled around elements.** `Terminal.vue:139-140`,
   `Help.vue:33-42`, `Contact.vue:199-201`, `CommandPalette.vue:194`,
   `Unknown.vue:10-17` and `RoleDetail.vue:74-75` each wrap a `<span>`, a
   `<button>` or a `<SessionKeyCap>` in the middle of a sentence. Splitting
   them into fragments fixes English word order into every language. They need
   vue-i18n's component interpolation (`<i18n-t>` with named slots), which
   `bundle.fullInstall: true` keeps
   ([options](https://i18n.nuxtjs.org/docs/api/options)).
4. **Concatenation that assumes English order.** "Read " + name
   (`Recommendations.vue:169-174`), "— title, company"
   (`Recommendations.vue:142`), "© year name" (`Footer.vue:12`), "— name,
   headline" (`Terminal.vue:115`), "Last login: … on ttys002"
   (`Terminal.vue:110`). Each becomes one message with named parameters.
5. **Pluralisation by hand.** `trimmed === 1 ? 'block' : 'blocks'`
   (`Terminal.vue:144`), and "N words", which prints "1 words" for a one-word
   quote (`Recommendations.vue:180`). vue-i18n uses pipe-separated forms and,
   for languages such as Russian, a `pluralRules` function per locale
   ([pluralization](https://vue-i18n.intlify.dev/guide/essentials/pluralization)).
6. **Validation messages tied to the schema.** The schema deliberately returns
   a rule name, not copy (`shared/enquiry.ts:29-35`), and `Contact` maps
   field and rule to a sentence (`Contact.vue:72-81`). That seam is already
   right: the map becomes keys such as `contact.complaint.name` and
   `contact.complaint.tooLong` with `{limit}`. The sentence is handed to
   `setCustomValidity` (`Contact.vue:93-100`), so it must be a plain string,
   and the effect has to re-run when the locale changes.
7. **State used as a label.** `LABELS[state] ?? 'send'` (`Contact.vue:50-53`,
   `179`) prints `EnquiryState` values; `{{ choice }}`
   (`CommandPalette.vue:222`) prints `ThemeChoice` values that are also the
   flags of `theme --light` (`useSession.ts:112-119`). The value stays the
   identifier; a message keyed by it is what prints.
8. **A group name used as a DOM id.** `group.name` is the heading, the
   `v-for` key and part of an element id (`CommandPalette.vue:159-169`). A
   translated name with a space in it breaks the id. The group needs a stable
   key beside its label.
9. **Recommendations are verbatim by definition.** "A verbatim quote … taken
   from Pavel's LinkedIn profile" (`CONTEXT.md:115-117`), "Never paraphrased,
   never trimmed for fit" (`app/data/recommendations.ts:15-18`), and the page
   says "Verbatim from LinkedIn" (`Recommendations.vue:113`). A translated
   quote is no longer verbatim. Either the quotes stay in English in every
   locale with the provenance line saying so, or they are translated and
   marked as translations. This is a product decision.
10. **Role periods are built from English.** `MonthYear` is a template type
    over `'Jan' | … | 'Dec'` (`app/data/experience.ts:66-70`), `exactPeriod`
    prints it as written (`:106`) and `period` appends the word `'now'`
    (`:103-105`). ADR-0009 left this for the i18n work
    (`docs/adr/0009-dates-are-formatted-for-the-visitor-after-load.md:56-57`).
    The clean form is machine dates in the data (`2023-06`) formatted through
    a named `Intl` format, with "now" a message.
11. **Prose is data, not UI copy.** The Background and each Role's account
    are arrays of paragraphs typed by `Profile` and `Role`. As vue-i18n
    messages they become arrays read with `tm()` and `rt()`, lose the
    interface types, and fall under `no-unused-keys`. As per-locale modules
    (`app/data/<locale>/profile.ts`) they keep their types and ADR-0007's
    props, and a missing field is a type error. ADR-0010 points at the second
    (`docs/adr/0010-content-lives-in-typed-modules.md:37-39`).
12. **Things that are not translated at all.** `ppadron.page`, `ttys002`,
    `$`, `·`, `/`, `→`, `K`, `esc`, `Tab`, `⌘`, `GitHub`, `LinkedIn`,
    technology names in `skills`, `stack` and `tech`, company and people
    names. The raw-text rule flags the ones in templates, so they go in its
    `ignoreText` or `ignorePattern`.
13. **`error.vue` is unstyled English** (`app/error.vue:10-16`) and sits
    outside the Session. It needs keys too, and it renders when the i18n
    plugin itself may have failed.

### What the house rules and ADRs constrain

- **ADR-0007, pure Outputs.** "Interface copy … stays in the component that
  speaks it and never arrives as a prop"
  (`docs/adr/0007-output-components-are-pure.md:51-53`), so an Output calling
  `useI18n()` or `$t` for its own copy is consistent with it. But the same
  record says an Output's interface "is its props and emits, and nothing else"
  (`:36`), and ADR-0009 says "Output components still see no locale"
  (`docs/adr/0009-dates-are-formatted-for-the-visitor-after-load.md:53-54`).
  Reading the i18n instance is a new ambient dependency for every Output; it
  needs an ADR that says so, and Content must keep arriving as props, already
  in the right language, from `Terminal`.
- **ADR-0008, prerendered page.** No per-request locale. Messages must be in
  the bundle or prerendered, not served by a function; every locale route
  needs a prerender rule; `nuxt generate` stays banned.
- **ADR-0009, dates.** `useDateContext` keeps the time zone and takes the
  locale from the library; `pickLocale` (`app/utils/date-format.ts:38-52`)
  goes away or becomes the library's detection.
- **ADR-0010, Content.** Reopened by this work, by its own last paragraph.
- **ADR-0012, palette.** The language choice belongs in the palette beside
  the theme, and as a meta command.
- **No type assertions.** A key built from a union
  (`` `contact.complaint.${key}` ``) is a `string` to typed `t()` and cannot be
  cast. Use a `satisfies Record<EnquiryField, …>` map of literal keys, the
  pattern `Contact.vue:83-87` already uses. The same goes for a locale code
  from the route or a cookie: find it in the locales list, never `as Locale`.
- **One `expect` per test.** Unaffected in shape. A test that checks one
  component in two locales compares one object, `{ en: …, es: … }`.
- **Same-name shorthand.** `:placeholder="t('…')"` is not a same-name binding,
  so nothing changes; a computed named `placeholder` would be `:placeholder`.
- **Comments.** A message that is a product decision keeps its why. JSON has
  no comments, so `Contact.vue:181-182` ("ADR-0003 makes this line literally
  true") stays in the template beside the `$t` call, not in the locale file.
- **Coverage gate.** `i18n/` is outside the allowlist (`vitest.config.ts:15-21`).
  If plural rules or a locale picker are written as functions, they belong in
  `app/utils/` or `shared/`, where the gate reaches them.
- **`slop/no-em-dash` is off on purpose** (`eslint.config.js:63-66`). If
  Markdown or JSON locale files are linted, the em dashes in copy stay.

## Migration outline

For `@nuxtjs/i18n`. Each step is test-first (`docs/agents/testing.md:21-31`)
and leaves the site shipping English unchanged until step 8.

1. **Record the decisions.** One ADR for the library, URL strategy and where
   messages live; one amending ADR-0007 and ADR-0009 for Outputs reading the
   i18n instance; one reopening ADR-0010 for per-locale Content. Add
   **Locale** and **Message** to `CONTEXT.md`.
2. **Spike on a Vercel preview** before anything else: `@nuxtjs/i18n` with
   one locale, `/` prerendered, `experimental.prerenderMessages: true`. Check
   that no `_i18n` function is deployed, that `.output/public/index.html`
   still exists, that hydration is clean, and what the client bundle gained.
   Also the first proof of pnpm's `trustPolicy` against the new dependency
   tree.
3. **Install and configure with English only.** `modules` gains
   `@nuxtjs/i18n`; `i18n: { locales: [{ code: 'en', language: 'en', file:
'en.json' }], defaultLocale: 'en', strategy: 'prefix_except_default',
detectBrowserLanguage: false, baseUrl: 'https://ppadron.page' }`. The
   hardcoded `htmlAttrs.lang` (`nuxt.config.ts:18-20`) is replaced by
   `useLocaleHead()` in `app/app.vue`.
4. **Where files live.** `i18n/locales/<code>.json` for Interface copy and
   `i18n/i18n.config.ts` for `datetimeFormats` and `pluralRules`, the module's
   defaults. Content in `app/data/<code>/{profile,experience,recommendations}.ts`,
   typed by the existing interfaces, chosen in `Terminal` by locale.
5. **Key naming.** Dot-separated, by owner then meaning, in the domain's
   words: `banner.lastLogin`, `banner.hint.printed`, `prompt.placeholder`,
   `palette.none`, `palette.keys.move`, `contact.field.from`,
   `contact.complaint.tooLong`, `recommendations.also`, `commands.whoami.label`,
   `keys.up`. One key per sentence, parameters named (`{count}`, `{limit}`,
   `{cmd}`), no key reused across components for strings that merely happen to
   match ("close" appears three times with three jobs). Enforce the casing
   with `key-format-style`.
6. **Move the Interface copy, one component per commit.** Order by risk:
   `Unknown`, `Background`, `RoleDetail`, `Experience`, `Colophon`, `Footer`,
   `KeyCap`, `Help`, `Recommendations`, `Contact`, `CommandPalette`,
   `PromptBar`, `Terminal`, `error.vue`, then the command labels in
   `useSession.ts`. Sentences with elements inside use `<i18n-t>`; plurals use
   pipe forms. Turn `no-raw-text` on per file as each lands.
7. **Dates.** Copy `dateFormats` into `datetimeFormats`, replace `formatDate`
   calls with `d(value, { key, timeZone })`, make `useDateContext` return the
   zone only. Change `RoleEntry` dates to machine form and format periods.
8. **Head.** Title and description become messages set with `useHead` or
   `useSeoMeta`; add `og:title`, `og:description`, `og:url`. Add a prerender
   rule per locale route beside `nuxt.config.ts:43-45`.
9. **Add the language setting.** A `lang` meta command and a palette group
   beside the theme, switching with `setLocale`. Under
   `prefix_except_default` that is a navigation to `/<code>`: the Transcript,
   the Enquiry draft and the history have to survive it or the switch reads as
   a reset. This is the step most likely to need design.
10. **Add the second locale.** Locale file, Content modules, `pluralRules` if
    the language needs them, prerender rule, one e2e assertion per locale.
11. **Update the docs that describe the page:** README, the Colophon copy if
    it changes, `docs/agents/testing.md`.

| `no-raw-text`                                     | No literal text in templates. Set its `attributes` option to cover `aria-label`, `placeholder`, `title` and `alt` on every element, as the run above did ([rule docs](https://github.com/intlify/eslint-plugin-vue-i18n/blob/master/docs/rules/no-raw-text.md)) |
| `no-missing-keys`                                 | A `t('…')` with no message fails                                                                                                                                                                                                                                |
| `no-missing-keys-in-other-locales`                | A key in `en.json` missing from another locale fails                                                                                                                                                                                                            |
| `no-unused-keys`                                  | A message nothing reads fails                                                                                                                                                                                                                                   |
| `no-dynamic-keys`                                 | Keys are literals, so the two rules above can see them                                                                                                                                                                                                          |
| `valid-plural-forms`                              | Each locale has the plural forms its rule needs                                                                                                                                                                                                                 |
| `key-format-style`, `no-duplicate-keys-in-locale` | Hygiene                                                                                                                                                                                                                                                         |

Settings: `localeDir: './i18n/locales/*.json'` and
`messageSyntaxVersion: '^11.0.0'`.

What lint cannot see:

- **Strings in `<script>` and `.ts`.** `no-raw-text` covers "template or JSX"
  only. `LABELS` and `complaint` (`Contact.vue:50-81`), `KEYS`
  (`KeyCap.vue:12-16`), the group names (`CommandPalette.vue:50-52`) and the
  command labels (`useSession.ts:51-106`) pass it untouched. Typed keys
  (`experimental.typedOptionsAndMessages: 'default'`) make a wrong key a type
  error but do not find a string that never became a key. A unit test in the
  style of `test/unit/text-roles.test.ts`, which already scans source for a
  barred pattern, can hold a short allowlist of files permitted to contain
  string literals that reach the DOM.
- **Content.** Per-locale modules are checked by the type system (a missing
  field does not compile) and by `test/unit/content.test.ts` run once per
  locale: same Roles, same slugs, same order, no placeholder.
- **The page as served.** One e2e assertion per locale that `<html lang>`
  matches and that the page contains no string from the default locale's
  file where a translation exists.

### Test strategy

- **`test/nuxt` gets the real module.** The `nuxt` environment boots the app
  with its modules, so components render real messages. No `useI18n` mock;
  ADR-0007's "a test that mounts an output never fakes a session" extends to
  never faking the translator.
- **Assertions stop spelling copy.** The repo's rule for Content is "Read the
  expected value from the data module; never spell it out"
  (`docs/agents/testing.md:166-168`). The same rule for Interface copy: import
  `i18n/locales/en.json` and assert against `en.contact.complaint.name`, so a
  copy edit touches one file. `roleOf` (`test/nuxt/text-role.ts:31`) takes the
  message the same way. About 75 assertions change (table above).
- **Behaviour that is not copy gets its own tests:** each plural form of the
  dropped-blocks notice (0, 1, 2, and 5 for a Slavic rule), word order in the
  `<i18n-t>` sentences in a second locale, `setCustomValidity` re-run on
  locale change, the palette's language group.
- **`test/unit` stays Nuxt-free** (`docs/agents/testing.md:213-214`). Plural
  rules and any locale-matching function are plain functions tested there.
- **e2e.** `test/e2e/ssr.test.ts:89-91` pins `lang="en"` for `/`; add the same
  for each locale route, the `hreflang` set, and that each
  `public/<code>/index.html` exists, the way `/` is checked today
  (`docs/agents/testing.md:179-184`). The hydration check in a browser context
  with a foreign `locale` (`docs/agents/testing.md:247-256`) now has a second
  thing to catch: a locale switch during hydration.
- **`pnpm look`** for each locale: longer strings in the Prompt bar, the
  palette rows and the Contact labels (`w-24`, `Contact.vue:121`) are where a
  translation breaks layout.

## Open decisions

1. **Which locales.** Spanish and Russian are the two the author can review
   himself; anything else needs a reviewer. Is there a client market that
   justifies either?
2. **URL strategy.** `prefix_except_default` (recommended) or `no_prefix`.
   The second keeps one URL and one file, but the served HTML is always
   English, the translation appears after hydration, and search engines never
   see it.
3. **Detection.** Off with a visible setting (recommended), or a client-side
   redirect from `/` on first visit. A server redirect needs a function in
   front of the page, which ADR-0008 rejects.
4. **Is Content translated**, or only the Interface copy? Translating the
   chrome around English prose is the cheap half and reads as unfinished.
5. **Recommendations:** verbatim English everywhere, or translated and
   labelled as translations.
6. **Where translated Content lives:** per-locale typed modules
   (recommended) or message files. Decides whether a translation platform can
   see it at all.
7. **Command aliases per locale:** none, or a localized set per language.
8. **Does switching language keep the Transcript?** Under prefixed routes a
   switch is a navigation.
9. **Role titles and company descriptions:** job titles such as "Lead
   Frontend Developer" (`app/data/experience.ts:118`) are often left in
   English in Spanish and Russian CVs.
10. **Typed keys:** accept an experimental flag, or rely on lint alone.
11. **Translation workflow:** by hand in the repo (recommended), or a
    platform; and whether a machine draft is acceptable as a starting point
    for first-person copy.
12. **A licence for the repo.** Unrelated to i18n in itself, but it is what
    gates every open-source translation programme.

  $450" is billed per were not.

  GitHub behaviour were not read from their docs, since none has a free plan
  that fits.

  403; "only for public projects" is from the pricing page.
- **Whether any platform reads vue-i18n syntax natively.** Tolgee, Weblate,
  SimpleLocalize and Fink list generic or i18next JSON, not vue-i18n. Plain
  nested JSON will import; pipe-separated plurals and `@:linked` messages are
  vue-i18n's own and may be treated as plain text. _Inferred_, not tested.

  `_i18n` function once `prerenderMessages` is on, and that detection cannot
  redirect a CDN-served `/`, are inferences from the docs; step 2 of the
  outline exists to test them.
- **Bundle cost.** The only figures are nuxt-i18n-micro's benchmark of its
  competitor. No measurement was made on this repo.
- **The `nuxt` Vitest environment with the module loaded.** Inferred from
  Nuxt's testing docs; the module's own docs say nothing about tests.
- **pnpm `trustPolicy: no-downgrade` against the new dependency tree.** The
  top-level packages carry provenance; their transitive dependencies were not

- **Azure's price** is from Microsoft's retail prices API for West Europe; the

- **Nuxt-intlayer** was read from one guide only; its prerender, detection and
