# Experience is the only proof surface; there is no Work section

The previous site carried an empty "Work — coming soon" section alongside Experience, and it stayed empty for years. The two were never meaningfully distinct: Pavel's freelance client work is under NDA and cannot be shown, and the work that is genuinely worth showing is the work he did in the roles already listed under Experience. We deleted Work permanently and made Experience the single proof surface, rewriting each Role to lead with what was built rather than the job title held.

## Considered Options

- **Anonymised case studies** ("a European food-delivery platform, ~40k MAU: rebuilt checkout in Vue 3, LCP 4.1s → 1.6s"). Rejected because the work worth describing that way is the employed work, which Experience already covers — the case studies would have duplicated it under a second heading.
- **Keeping "coming soon".** Rejected: a section that has been coming for years reads as abandonment, not momentum. It was the one element on the old site that actively cost credibility.
- **Renaming Experience to "Work".** Rejected: the entries are employment with companies and date ranges. Labelling employment as "Work" is the same category error in the opposite direction.

## Consequences

A visitor arriving at a developer's portfolio will not find a projects gallery, which is genuinely surprising for the genre. This is deliberate and should not be "fixed" by scaffolding a Work or Projects section later. If public work ever becomes available, reopen this decision explicitly rather than quietly adding a section.

The repository itself is the compensating public work sample: it is linked from the footer and is made public at launch, which is why that is a blocking release item.
